# Project Structure

**Ch'rps** is a Next.js 14 App Router application written in TypeScript, styled with Tailwind CSS, and deployed on Vercel — Next.js API routes act as the backend (serverless functions), with MongoDB (via Mongoose) as the persistence layer. There is no separate backend service; `app/api/**/route.ts` files are the entire API surface. A native iOS shell (Capacitor, server-URL mode — see "iOS Native Shell" below) wraps this same deployed web app; it does not change or duplicate any of the above.

Ch'rps is a multi-tenant, restaurant-style shift-check app — structured checklist tasks (`form`-type: numeric readings, yes/no fields, or checklist sub-items) organized into task lists (Opening/Mid-Shift/Closing/manager-created custom lists) plus one or more standalone anytime task lists. Every company using Ch'rps is a `Company` tenant, and a manager can create/rename/delete task lists and set their day-of-week schedule — see CLAUDE.md's Multi-Tenancy section and `docs/features/task-lists.md`. It's a lean fork of an earlier personal habit/routine tracker; the personal-habit framing (timer-based Countdown/Stopwatch/Checkbox item types as the primary type, the Sunday "Routine Review" time-variance feature) and an even earlier virtue/goals/quotes layer ("A Good Man") have both been retired, and the product vocabulary itself was later renamed from "Routine"/"Habit" to "TaskList"/"Task" throughout the codebase and docs — see `CLAUDE.md` for the current product brief and its Vocabulary note. There used to be a **native iOS App Intents/Shortcuts layer** (`ios/App/App/AppIntents/`, `ios/App/App/ChrpsAPI.swift`) carrying pre-pivot "Habit"/"Routine" naming — deleted outright rather than renamed, since Shortcuts integration was never load-bearing for this app; see "iOS Native Shell" below for the removal note. The `RoutineActivity` Xcode target/Widget Extension (the Live Activity) still carries the same pre-pivot naming and is *not* going anywhere — that one's a deliberate, documented exception, not an oversight.

## iOS Native Shell

The iOS app is a Capacitor wrapper in **server-URL mode**: the native `WKWebView` loads the live production Next.js deployment directly (`capacitor.config.ts`'s `server.url`), the same as a browser tab, just without browser chrome and with its own icon/splash. There is no static export and no bundled frontend — the Next.js codebase requires zero changes for this to work, and any future edits to `app/`/`components/` ship to the iOS app automatically the next time production redeploys (no App Store review needed for content changes, only for native shell changes).

### App Intents/Shortcuts and the external API — removed entirely

`ios/App/App/AppIntents/` (`TriggerHabitIntent.swift`, `HabitEntity.swift`, `HabitEntityQuery.swift`, `ChrpsShortcuts.swift`) and `ios/App/App/ChrpsAPI.swift` used to hold this app's native Siri/Shortcuts integration — the "Trigger Habit" App Intent, appearing in Shortcuts/Siri/Spotlight automatically, backed by a live task picker and a Keychain-based API key. **Deleted outright**, along with everything it depended on or was depended on by:

- **Native Swift**: `ios/App/App/AppIntents/` (all four files), `ChrpsAPI.swift`, `ApiKeyBridgePlugin.swift`, `KeychainHelper.swift` — the last two because nothing else read/wrote the Keychain-stored API key once the App Intents were gone (the Live Activity's own old use of Keychain was already removed separately, see [`live-activity.md`](features/live-activity.md#open-app-button)). Removing traditionally-managed (non-filesystem-synchronized) Xcode files needs `project.pbxproj` surgery via the `xcodeproj` Ruby gem (`Xcodeproj::Project`, `file_ref.remove_from_project`), not just deleting them from disk — the `AppIntents` `PBXGroup` and every file's `PBXBuildFile`/Sources-phase entry had to go too, or the project would reference missing files. `App.entitlements`/`RoutineActivity.entitlements`'s `keychain-access-groups` were also removed — nothing needs Keychain sharing between the App and RoutineActivityExtension targets anymore. `MainViewController.swift`'s `capacitorDidLoad()` no longer registers `ApiKeyBridgePlugin`.
- **Backend**: the entire `app/api/external/` route group (`trigger-task`, `start-timer`, `complete-active-task`, `tasks`, `nfc/[tagCode]`), `app/api/user/api-key/`, `lib/api-key.ts`, `models/AppIntentLink.ts`, `POST /api/nfc-tags/generate` (its only purpose was minting a tag reachable solely through the now-deleted `GET /api/external/nfc/[tagCode]`), `lib/task-trigger.ts`'s `completeActiveTask()` (its only caller was the deleted `complete-active-task` route), `middleware.ts`'s `api/external` matcher exclusion, and `User.apiKey`/`User`'s unique-sparse index on it (schema field removed; a lingering index on the live MongoDB collection from before this change is harmless dead weight, not cleaned up automatically — drop it by hand if it matters).
- **Web UI**: the Profile page's "External API Key" card and its fetch/copy/Keychain-push logic, `components/NativeBootstrap.tsx`'s API-key-to-Keychain push, `lib/native/api-key-bridge.ts`, `components/NfcTagLinkedSetup.tsx`'s Shortcut-building instructions (now a plain confirmation), and Manage Task List's "Siri & Shortcuts" connection status / raw-`_id` displays (both existed solely for this surface).
- **Docs**: `docs/features/app-intents.md` and `docs/api/external-api.md` deleted entirely; `docs/features/nfc.md` (its former second trigger path — the Shortcuts silent-trigger flow — and `triggerTask()`'s case-dispatch explanation, preserved there) and every doc cross-referencing either deleted file were updated in the same pass.

**Why removed, not just deprecated in place**: `TriggerHabitIntent`/the external `trigger-task`/`start-timer` endpoints and the Live Activity's old "Done" button shared the identical gap against the current `form`-task-based data model — neither could collect a form task's field answers or supply a verified NFC scan, so a blind trigger/complete either silently recorded a check with no data captured or failed outright with no way to show why (see [`nfc.md`](features/nfc.md)'s `assertNfcVerified` note and its `triggerTask()` case-dispatch section). The Live Activity side was fixed by replacing its button with one that opens the app instead (see [`live-activity.md`](features/live-activity.md#open-app-button)). Shortcuts integration was judged not load-bearing for this app going forward, so rather than build an equivalent app-opening redirect for it too, the whole surface was removed.

**One remaining capability loss worth knowing about**: opening a guided Task List Session for an *anytime* task list (no `startTime`, no in-app "Start Tasks" button by design) used to be reachable only through the external API's `routineGroupId` param — see [`anytime-tasks.md`](features/anytime-tasks.md). That's now genuinely impossible, not just undocumented; accepted as fine since nothing in practice ever called it that way.

**What's still there and still uses pre-pivot naming, deliberately**: the `RoutineActivity` Xcode target/Widget Extension (`ios/App/RoutineActivity/` — the Live Activity) still carries "Routine"/"Habit"-era naming (`RoutineActivityAttributes`, etc.) — a full native/Xcode-target rename is separate, higher-risk work that needs Xcode itself to verify, not something safely doable as a text-only pass — see CLAUDE.md's Vocabulary note. This is unrelated to and unaffected by the App Intents removal above; the Live Activity itself is very much still a live, maintained feature.

`ChrpsAPI.swift`/`ChrpsShortcuts.swift`'s Ch'rps-rebrand naming (previously `BeOneAPI.swift`/`BeOneShortcuts.swift`, the "Be One" name Siri/Shortcuts used to show) is now moot — both files are deleted, so there's no lingering "Be One" naming debt left to track either.

**Google OAuth inside the WebView:** Capacitor's default behavior sends navigation to domains outside the app's own origin (like `accounts.google.com`) out to the system Safari app. That breaks Auth.js's sign-in flow, because the CSRF token and session cookies set when the flow starts live in the app's WebView cookie jar, not Safari's — the callback lands back in Safari's separate jar and Auth.js can't validate it, surfacing as a generic `/api/auth/error` "Server error" page. The fix was to allowlist `accounts.google.com` in `capacitor.config.ts`'s `server.allowNavigation`, keeping the whole OAuth round-trip inside the app's own WebView and its single cookie jar. This did **not** require routing through `@capacitor/browser`/`ASWebAuthenticationSession` or Universal Links — the simpler in-WebView allowlist was sufficient once tested against the real production OAuth flow in the iOS Simulator.

**Sign in with Apple, by contrast, does need `ASWebAuthenticationSession`:** unlike `accounts.google.com`, iOS refuses to run `appleid.apple.com` inside a plain WKWebView at all regardless of `allowNavigation`, and (unlike the Google case) the sheet it hands navigation to doesn't share a cookie jar with the app's own WebView — signing in there alone left the app itself signed out. This needed a dedicated in-app-browser handoff mechanism, built and rebuilt across several live-device-diagnosed iterations — see [`native-apple-signin.md`](features/native-apple-signin.md) for the full flow, why three earlier designs each failed on a real device, and why extensive debug logging is deliberately still in place.

**Branding:** `assets/icon.png` and `assets/splash.png`/`splash-dark.png` are generated once from the Ch'rps bird/chirp logo mark (white background, the mark in its usual blue/green; the splash screen additionally carries the "Ch'rps" wordmark and its tagline below the mark) and then expanded into the full `Assets.xcassets` icon/splash set via `npx capacitor-assets generate --ios`. Re-run that command after editing the `assets/` masters, then `npx cap sync ios`.

**White flash between splash and content:** `WKWebView` defaults to a white canvas until the remote page's own CSS paints — a real, visible gap in server-URL mode since content loads over the network rather than instantly from a bundle. Fixed via `capacitor.config.ts`'s `ios.backgroundColor` (Capacitor's official config for the WebView's own background, applied before any content loads) plus pinning the same color on `ios/App/App/Base.lproj/LaunchScreen.storyboard`'s root view as a second guard against letterboxing. Verified by rapid-fire screenshotting through a cold launch, not just eyeballing it once.

**Native bootstrap:** `components/NativeBootstrap.tsx` (mounted in `app/layout.tsx`, `Capacitor.isNativePlatform()`-guarded) registers Live Activity push-token forwarding on every native cold start (see live-activity.md) — it used to also push the user's API key into Keychain here via a custom `ApiKeyBridgePlugin`, the first custom native plugin in this project; removed along with the rest of the App Intents layer above. Three other custom Swift plugins remain: `NfcScanPlugin.swift` (in-app tag reading, see nfc.md), `LiveActivityPlugin.swift` (Lock Screen timer control, see live-activity.md), and `AppleSignInSessionPlugin.swift` (native Sign in with Apple handoff, see native-apple-signin.md) — `KeychainHelper.swift`, which none of these ever needed (only the now-deleted `ApiKeyBridgePlugin`/App Intents code read it), is gone too. Two more native capabilities have since been added as official/community Capacitor plugins rather than custom Swift (no `MainViewController.swift` registration needed): `@capacitor-community/sqlite` (the offline local cache/outbox) and `@capacitor/network` (connectivity detection) — see offline.md.

## Secrets Policy

**This file and every file it links to must never contain secret values, API keys, or connection strings.** Reference environment variable *names* only, never their actual values:

- `MONGODB_URI`
- `AUTH_SECRET`
- `AUTH_GOOGLE_ID`
- `AUTH_GOOGLE_SECRET`
- `SKIP_AUTH` (local-dev-only auth bypass — never set in production)
- `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_PRIVATE_KEY` (Live Activity push, see `lib/apns.ts` and `features/live-activity.md`)
- `QSTASH_TOKEN`, `QSTASH_URL`, `QSTASH_CURRENT_SIGNING_KEY`, `QSTASH_NEXT_SIGNING_KEY` (shift-window alerts — the missed-list sweep and per-list start-time reminder schedules, see `app/api/cron/check-missed-lists`, `lib/qstash-schedules.ts`, and `features/notifications.md`)

`.gitignore` excludes `.env*.local` (covers `.env.local`, `.env.development.local`, etc.), but **not** a bare `.env` or `.env.production` — if either of those is ever added, extend `.gitignore` before committing.
